# PerRoute 3.5: what is verified, and what needs a real machine

## Verified by the automated suite (`.\test.ps1`)

| Area | How |
|---|---|
| Snapshots, comparison, restore plans | Pure tests: PerRoute's values are recognised, values set by others are never restored over, an outdated saved copy is dropped, the clean baseline survives the history limit. |
| Network restore in the controller | Fake machine: refused while connected, proxy put back from the baseline, leftover cores stopped, the engine only restored with Administrator rights, a snapshot kept before the restore. |
| Startup health | Failed starts are counted per version, a healthy start or clean exit resets them, the updated-from version is remembered. |
| Subscription intelligence | Header parsing (usage, quota, expiry, base64 titles), change detection, findings, link never stored; end to end with a local HTTP provider: insights, large change, failure count, removal. |
| Gaming score | Steady, jittery, lossy, no-UDP and unreachable servers. |
| Gaming probe | Real Xray core: 20 TCP and 20 UDP round trips through a local VLESS server whose UDP is echoed. |
| Comparisons | Fake timer: better, similar, worse, failed candidate, stopped test, failure counting. |
| Recipes | Round trip as file and text, checksum, refusal of unsafe values and paths, import plan (duplicate, conflict, missing app, configured app), apply and undo in the controller. |
| Workspaces | Storage, slots, validation, launch command (proxy, profile folder, DNS, QUIC, WebRTC), isolated config with global rules only, port range. |
| Local network | Ranges, ARP parsing, network identity, policy persistence, rule order in the generated config, engine `bypassLan` only when blocking. |
| Temporary servers | Planner (own route, ignored when the server is gone, per-app only); runtime layout plans (add, remove, renamed indexes, balancers refused); controller (no permanent change, restart fallback, in-place changes, expired entries ignored); real Xray core: started and ended in place while another app's open connection kept working. |
| Doctor and Safety Center | Clock, DNS, unselected app, blocking rule, tunnel failure explained from the core's log, exit addresses, kill switch, name lookups, shadowed rules, repairs. |
| Interface | Every new screen and dialog rendered off-screen in both designs (`.\gradlew.bat renderUiSnapshots`, scenes `*-A0` to `*-A9`). |

## Needs the installed app on a real computer

- [ ] Install 3.5.0 over 3.0.0: `PerRoute.rollback` exists next to the installation, *Settings > Recovery* offers to go back to 3.0.0, the Start menu has **PerRoute Recovery**, and PerRoute opens without Administrator rights after setup.
- [ ] **Go back to 3.0.0** from Settings: one Administrator prompt, PerRoute closes, 3.0.0 opens with the same servers and apps.
- [ ] Settings > Updates > Install update: the Administrator prompt appears and PerRoute closes.
- [ ] Connect in System proxy mode, end PerRoute from Task Manager, open **PerRoute Recovery**: it lists the leftover proxy; **Restore network settings** clears it and browsers work again.
- [ ] Same, but set another proxy in Windows settings before restoring: the other proxy is kept.
- [ ] Smart per-app with the kill switch on, end PerRoute from Task Manager, restore from the recovery tool: one Administrator prompt, the engine stops, the apps reach the internet directly again.
- [ ] Temporary server from Quick Access in the tray for a selected app: the app's traffic leaves through the chosen server (check its exit address), other apps keep theirs, and it returns after the chosen time.
- [ ] A browser workspace on another server than the main one: whatismyip in the workspace shows the workspace's server; the same site in the normal browser shows the main server or the direct address; closing the workspace window stops its route.
- [ ] Mark the current Wi-Fi as not trusted, reconnect: a routed browser cannot open the router's admin page of a printer or NAS on that network, while the internet still works; the trusted setting restores access.
- [ ] Gaming test against your real servers: servers known to carry UDP show **UDP Yes**.
- [ ] Compare with a live route against a real candidate: the live route's apps are not interrupted during the test.
- [ ] Uninstall: PerRoute closes, its proxy and engine changes are put back, and both the installation and `PerRoute.rollback` are removed.
