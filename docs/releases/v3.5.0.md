# PerRoute 3.5.0

A safety net for your network, servers you can try without risk, routes you can share, a browser per purpose, and a Doctor that says why something does not connect.

## Downloads

| File | Description |
|---|---|
| `PerRoute-Setup-3.5.0.exe` | Full installer. One Administrator approval installs PerRoute, the per-app engine and PerRoute Recovery. |
| `PerRoute-Portable-3.5.0.zip` | Portable build. Extract and run `PerRoute.exe`. |
| `update.json` | Signed update manifest used by *Settings > Updates*. |

**Requirements:** Windows 10 or 11, 64-bit. No Java installation is needed.

## New

- **Network Time Machine** (*Settings > Recovery*). PerRoute takes a snapshot of the settings it touches when it starts, when you connect and when you disconnect: the Windows proxy, its start-up recovery entry, the per-app engine's app list and service, leftover cores, plus your DNS servers, gateways and WinHTTP proxy for reference. Compare any snapshot with now and see, line by line, whether PerRoute, Windows or another program made each change. **Restore network settings** undoes only PerRoute's own leftovers; a proxy another program set is left exactly as it is.
- **PerRoute Recovery.** A small program of its own in the Start menu that puts the network back, and can go back a version, even when PerRoute itself does not open. It asks for Administrator approval only for the per-app engine and for a rollback.
- **Safe update and rollback.** The installer keeps the version it replaces. If a new version does not finish starting twice in a row, PerRoute offers to go back; you can also go back from *Settings > Recovery* or *Updates*. Your servers, apps and settings are kept. Installing a downloaded update now shows the usual Administrator prompt and closes PerRoute so its files can be replaced.
- **Temporary servers.** Put one app on another server for 15 minutes to 4 hours, from the app's panel, the Connection screen, a server's menu or Quick Access in the tray. Its saved route and your rules are not touched, and it goes back by itself. While connected only that app's route changes; with route monitoring on, the change happens inside the running core and other apps keep their open connections.
- **Compare with a live route** (Shadow Routing). From a server's menu or the Connection screen: the live route and the candidate open the same HTTPS sites side by side, three times each, alternating which goes first. The sites are the ones the route's apps were seen using in this session, then common sites. The live route is never changed. The result says which is faster and more reliable, and offers to switch the route or to try the candidate for 30 minutes.
- **Routing recipes** (*Profiles > Recipes*). Share your rules and app routes as a file or as one line of text, without servers, addresses, subscription links, passwords or folders: apps are named by their file name and servers become slots. Importing shows every rule (added, already there, or overruled by one of yours), finds the apps on this computer, lets you point each slot at one of your servers, and keeps a snapshot so **Undo the last recipe** puts everything back. Recipes from others are checked strictly: unknown values, local files and oversized input are refused.
- **Browser workspaces** (*Tools > Workspaces*). A browser profile of its own for work, personal use or anything else, each on a route of its own while every other app keeps its own route. A workspace has its own profile folder, its own core and loopback port, sends names to the far side of the route, and keeps QUIC and WebRTC inside it. If its route stops, its window has no connection rather than a direct one. Works with Chrome, Edge, Brave, Vivaldi and Chromium, connected or not.
- **Local network** (*Settings > Local network*). See the networks you are on and the devices Windows has talked to. Names that only exist locally (`printer.local`, `nas.lan`, `router.home.arpa`) now stay on your network instead of going to the proxy server. Mark a network such as café Wi-Fi as not trusted, and routed apps cannot reach its devices; its router and DNS stay reachable.
- **Connection Doctor** (*Tools > Health*). Pick an app (and optionally a site) that does not work. The Doctor checks from the outside in: your own connection, DNS and clock, the core and the per-app engine, the Windows proxy, the server, the tunnel (reading the core's own log for the reason: certificate, Reality, account, timeout, reset), the app's selection and the rule for the site. It names the most likely cause and offers a repair, which runs only after you confirm.
- **Routing Safety Center** (*Tools > Health*). Tests every route's exit address against your own, explains where name lookups go, checks that the per-app engine redirects PerRoute's list of apps and what the kill switch does, finds rules that are not loaded in the running core and rules that can never apply because an earlier one decides first.
- **Subscription intelligence.** The provider's usage, quota and expiry (`subscription-userinfo`), its title and suggested update interval are shown under the subscription's details in *Servers*, with each update's added, removed and changed servers. Expired subscriptions, data used up, failing or stale updates and unexpectedly large changes are flagged, and the Doctor mentions them when a server fails.
- **Gaming test.** Twenty round trips over TCP and twenty over UDP through each server, on a core of its own: steady latency, the slowest twentieth, jitter, lost packets and whether the server carries UDP at all. The score favours steadiness; a server without UDP is capped. Sort servers by **Best for gaming**.

## Changed

- **One logo everywhere.** The lime route mark of the New design is now PerRoute's logo in both designs, in Quick Access, and as the window, taskbar, tray, installer and program icon.
- **Restoring the Windows proxy is safer.** PerRoute only puts its saved settings back while the proxy is still its own. If another program (a VPN, a corporate tool) set a proxy since, that setting is kept and PerRoute's outdated copy is dropped.
- The installer opens PerRoute as the signed-in user after installing, instead of with the installer's Administrator rights.
- The uninstaller closes PerRoute and puts its network changes back before removing the files, and also removes the kept previous version.
- Tests that start a core of their own (real tunnel, speed, gaming, comparisons) pick a loopback port that is really free, so two tests never collide.
- Progress and error messages of the core and engine installers are in English, like the rest of the interface.

## Good to know

- Temporary servers, browser workspaces and the gaming test need the Xray core; temporary servers also need Smart per-app mode.
- A temporary server can be changed in place only when the core's control API is on: with route monitoring, an Auto app, or after the first temporary server of a session. Otherwise the first change restarts the core briefly.
- Embedded Xray profiles with balancers or an observatory cannot be changed inside a running core. When such a profile is the main server or the temporary server, starting and ending a temporary server restarts the core and briefly interrupts every routed app, as switching the main server does.
- Workspaces are separate browser profiles: you sign in to your accounts there once. They cannot share the profiles of a browser that is already open, because one browser process can only use one proxy.
- In Smart per-app mode Windows looks names up for the selected apps itself, with your normal DNS servers. The Safety Center says so and suggests secure DNS. Traffic itself goes through the tunnel.
- Recipes are checked for damage with a checksum; it does not prove who made one. Review the import preview before applying.
- Rollback goes back to the version the installer kept: the one installed right before this one.
