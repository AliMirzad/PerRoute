# PerRoute 3.0.0

Servers you can compare at a glance, a server per app that looks after itself, routes that recover on their own, real per-app bandwidth limits, a connection inspector, and portable backups.

## Downloads

| File | Description |
|---|---|
| `PerRoute-Setup-3.0.0.exe` | Full installer. One Administrator approval installs PerRoute and the per-app engine. |
| `PerRoute-Portable-3.0.0.zip` | Portable build. Extract and run `PerRoute.exe`. |
| `update.json` | Signed update manifest used by *Settings > Updates*. |

**Requirements:** Windows 10 or 11, 64-bit. No Java installation is needed.

## New

- **Network quality score.** Every server gets a 0–100 score with a label (Excellent, Good, Fair, Poor, Unavailable, Unknown), a confidence level and its age. Expand a server in **Servers** to see latency, jitter, success rate, stability, tunnel setup time and a plain explanation. A server without measurements is Unknown, never healthy; a server whose tunnel was never verified scores at most Good. Sort the list by quality.
- **Auto mode per app.** With Advanced routing on, each app can follow **Main**, use a **Manual** server, or use **Auto**. Auto gives the app a route of its own on the best measured server, keeps a working server until another one is clearly better (10 points by default) and the cooldown has passed (10 minutes), fails over at once when its server stops working, and never falls back to the direct route. You can limit it to favorites or a tag. Its current decision and the reason are shown in **Apps**.
- **Independent route recovery.** Each live route is checked through its own port once a minute. A route that stops answering is retried with growing delays (2, 4, 8, 16, 32 s), rebuilt inside the running core without touching other routes, and after five failures re-checked every two minutes until it answers. **Connection** shows the attempt, the countdown, a short timeline, whether the kill switch is holding the route's apps, and that there is no direct fallback.
- **Changing one route no longer restarts the others.** Switching the main server, an Auto failover and rebuilding a stuck route replace only that route's outbound in the running core: other apps keep their open connections. Embedded Xray profiles still restart the core.
- **Per-app bandwidth limits.** Download and upload limits per app, shared by all of its connections, for TCP and UDP. They are enforced by the new **traffic gateway** and can be changed while connected. Each app shows whether its limit is Enforced, Throttling, Pending or Not enforced, and why.
- **Connection inspector** (*Diagnostics > Inspector*). Live connections of the selected apps with destination, sniffed domain, protocol, route, status and traffic, with filters and a pause button. What your setup says should happen (**Configured**), what the core actually did (**Observed**, from its own log) and what a route check confirmed (**Verified**) are always shown apart. Nothing is stored.
- **Bandwidth by app** in **Traffic**: current rate, session totals, limits, utilization and status for every selected app.
- **Backup & Restore** (*Settings*). Back up subscriptions, servers, app assignments, rules, profiles and preferences to one file, encrypted with a password by default. Restoring previews the contents and compatibility, lets you point apps that are missing on this computer to their new location, offers Merge or Replace, writes a rollback snapshot first, applies everything in one step, and can be undone.
- **Settings > Routing** groups background quality checks, the Auto margin and cooldown, route monitoring and the traffic gateway.

## Changed

- The tunnel check now sends a small HTTP request through each route and only passes when the far side answers. Previously a SOCKS acknowledgement from the local core counted, which also passed for a server that was down.
- With the traffic gateway on, per-app traffic counters come from PerRoute itself; the core's statistics are no longer polled every second, which removes a short-lived `xray.exe` process launched every second while connected.
- A network change re-checks every route on its own and only restarts the core when none of them answers.
- Connection shows the main server's latency next to download, upload and session time.

## Upgrading from 2.x

Your setup is kept exactly as it was. No app is put in Auto mode and every app stays unlimited. On an upgraded installation, background quality checks, route monitoring and the traffic gateway start **off**; turn them on in *Settings > Routing*. Profiles from 2.x still apply.

## Good to know

- Bandwidth limits apply in Smart per-app mode only, and only to selected apps. Priority classes are not offered because they cannot be enforced without a shared bottleneck.
- The gateway runs inside PerRoute. If PerRoute stops unexpectedly while it is on, selected apps have no connection until PerRoute starts again; they are never sent direct.
- Loopback ports are not separated between Windows accounts. On a computer shared by several signed-in users, the core's routing API (enabled only while route monitoring or an Auto app is in use) could be reached by another user. See the security notes in the README.
- Changing an app's route mode, its Manual server or the app selection still needs a disconnect. Bandwidth limits and the main server can be changed while connected.
