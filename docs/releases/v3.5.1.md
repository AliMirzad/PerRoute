# PerRoute 3.5.1

Faster downloads and YouTube for routed apps, automatic updates, the right icons and routes for Microsoft Store apps after they update, and a few layout fixes. Coming from 3.0.0, you also get everything from 3.5.0: two interface designs, a safety net for your network, temporary servers, browser workspaces and more (see below).

## Downloads

| File | Description |
|---|---|
| `PerRoute-Setup-3.5.1.exe` | Full installer. One Administrator approval installs PerRoute, the per-app engine and PerRoute Recovery. |
| `PerRoute-Portable-3.5.1.zip` | Portable build. Extract and run `PerRoute.exe`. |
| `update.json` | Signed update manifest. PerRoute reads it from the latest release by itself; keep it attached. |

**Requirements:** Windows 10 or 11, 64-bit. No Java installation is needed.

## New

- **Automatic updates.** PerRoute checks the official releases when it starts and every six hours, with no link to enter. A new version is downloaded and verified in the background, and PerRoute asks once: **Restart and update** or **Later**. Windows asks for Administrator approval, the installer updates the existing folder without further questions, and the new version opens by itself, with your servers, apps and settings, and the previous version kept for a rollback. Every update must be signed with PerRoute's offline release key and match its size and SHA-256. **Update automatically** in *Settings > Updates* turns the download off; a feed of your own can still be entered.
- **Block QUIC** (*Settings > Routing*, on by default). Routed apps use HTTPS over TCP instead of QUIC (UDP 443). Browsers and YouTube fall back to TCP by themselves, as they do behind a system proxy. Carrying QUIC inside a server's TCP connection (gRPC, WebSocket, TCP+TLS or Reality) stacks two congestion controls and often made downloads and video noticeably slower than in clients that use a system proxy. Turn it off if an app needs QUIC; it applies from the next connection.

## Fixed

- **Microsoft Store apps after an update.** Store apps live in a folder named after their version, and the Store moves them on every update. PerRoute now finds the installed version on its own:
  - the per-app engine is given the app's current location, so an updated app keeps going through its route instead of silently leaving it (the Activity log says when this happens);
  - the app's real icon is shown again in Apps, Servers, Connection, Diagnostics and Traffic, instead of a letter;
  - the app is listed once, not as a missing old entry next to its new version;
  - saving the Apps page no longer drops an updated Store app from the selection.
- **Dark icons on dark surfaces.** Monochrome black logos are drawn on a light tile in the dark theme instead of disappearing. Icons are also read at a higher resolution, so they stay sharp at 150% scaling.
- **Long names.** A long server name no longer runs into the **Main** badge in Servers and Diagnostics, and a long app name no longer runs into the next column in Apps and Traffic, in both designs.
- **Title bar.** The empty square at the top left of the New design is gone; the logo and name start the bar.
- **App icon after an update.** The installer now makes Windows refresh its icons, so the taskbar, Start menu and desktop show the new icon instead of the old one Windows had cached.
- **UDP through the traffic gateway.** Larger socket buffers for UDP associations, so bursts are queued instead of dropped at high speeds.

## Also new since 3.0.0

3.5.0 was not published on its own, so these arrive with 3.5.1 too:

- **Two interface designs, light and dark.** *New* (a narrow rail with a detail panel, the default) and *Simple* (a wide menu with every section). Switch in *Settings > General*; nothing else changes.
- **Network Time Machine and PerRoute Recovery.** Snapshots of the network settings PerRoute touches, a comparison that says who changed what, and a restore of PerRoute's own leftovers, also from a separate Recovery tool when PerRoute does not open.
- **Safe update and rollback.** The installer keeps the version it replaces, and a version that cannot start is noticed.
- **Temporary servers.** One app on another server for 15 minutes to 4 hours; it goes back by itself.
- **Compare with a live route.** A candidate server and a live route open the same sites side by side.
- **Routing recipes.** Share rules and app routes as a file or a line of text, without servers, links, passwords or folders.
- **Browser workspaces.** Separate browser profiles, each on a route of its own.
- **Local network.** Your networks and devices, local names kept local, and local devices blocked for routed apps on networks you do not trust.
- **Connection Doctor and Safety Center.** Why something does not connect, with repairs you confirm, and real tests that protection works.
- **Subscription details.** Usage, quota, expiry and update history of every subscription, with warnings.
- **Gaming test.** Latency, jitter, packet loss and UDP support per server, and a score for games.

Full details: [3.5.0 release notes](https://github.com/AliMirzad/PerRoute/blob/main/docs/releases/v3.5.0.md).

## Is PerRoute slower than other clients?

We measured PerRoute's own data path on this release (loopback, no internet involved, so only PerRoute's overhead counts):

| Path | One download | 8 at once |
|---|---|---|
| Xray alone | 3.4–3.7 Gbps | 6.6–6.9 Gbps |
| PerRoute gateway, then Xray | 2.4–2.5 Gbps | 4.8–5.0 Gbps |

The gateway costs time per byte, but even its slowest result is many times faster than any home or mobile connection, so it is not what limits your speed. UDP through the gateway delivered as many packets as Xray alone up to 300 Mbps.

The difference people noticed came from QUIC: in Smart per-app mode, browsers and YouTube sent QUIC (UDP) through the tunnel, while clients in system-proxy mode make them use TCP. **Block QUIC** now gives routed apps the same behaviour. Two other things can matter:

- *Automatic speed tests* (*Settings > Automation*) download up to 10 MB from each of the 10 best servers after a ping pass. Turn them off if your connection is slow or metered.
- DNS settings and the domain strategy come from your server or profile, the same as in other Xray clients.

## Upgrading

Download the installer and install 3.5.1 over your current version (3.0.0 or 3.5.0) by hand this one time: earlier versions have no built-in update feed and trust an older release key, so they cannot find or accept it by themselves. Your servers, apps, routes and settings are kept, and the version it replaces is kept for a rollback. From 3.5.1 on, updates arrive automatically. **Block QUIC** starts on for everyone, including upgrades.
